## hashTable 哈希表
- 哈希表是一种基于键值对存储数据的数据结构。
- key 唯一，进行哈希（计算函数）运算， 得到一个索引。
- 索引指向一个存储位置， 存储着对应的 value。
- 当需要根据 key 查找 value 时， 直接根据 key 进行哈希运算， 得到索引， 然后从存储位置取出 value。

## dict 特点
- 查找和插入的速度极快，不会随着key 的增加而变慢
- 需要占用大量的内存，内存消费多。

## list 特点相反
- 查找和插入的时间随着元素的增加而增加；
- 占用空间小， 浪费内存很少

dict 可以用在需要高速查找的地方， 

## unhashable type
- dict 的 key 必须是可哈希的（hashable）， 也就是**不可变的类型**。
key = [1,2,3] 可变的 内容可以随时添加 
hash key 必须要唯一 ， 字符串 
dict 靠key计算value的存储位置， 如果key 可变，每次计算出来的结果可能不同， dict 混乱了。 
这个通过key 计算位置的算法成为哈希算法(hash)

## Set 
和dict 类似， 也是一组key 的集合，但不存value。
由于key不能重复，所以， 在set中， 没有重复的key。

set 和 dic 唯一的区别在于没有存储对应的value, set的原理和
dict 一样


## 再谈不可变对象

str 是不可变对象  而list 是可变对象

str 是变量 ， 可以被重新赋值
'abc'才是字符串对象 replace 作用在字符串对象'abc'上，
并没有改变'abc'内容。 返回了一个新的'Abc' 
所以， 对于不可变对象， 调用自身的任意方法， 也不会改变该对象的内容。 

变量提升时，函数优先于其他变量
如果定义了两个相同的函数， 那么最终生效的是最后一个函数。

## Prompt 的Principle 规则
- 撰写清晰、具体的指令
  让大模型回答符合预期， 不偏离主题或出错
  具体一些，为大模型提供完整的说明与背景信息（上下文）
  
- 引导大模型逐步推理

## llm api 调用 函数封装
